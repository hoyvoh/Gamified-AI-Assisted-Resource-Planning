# Database Schema Spec

**Developer Growth & Evidence-Based Performance Insight Platform — MVP**

> Schema targets **SQLite** (used in this MVP).
> Notes: UUIDs are stored as `TEXT`, generated at the application layer. Timestamps are `TEXT` (ISO 8601 UTC). JSON fields use `TEXT` with JSON serialization (SQLite ≥ 3.38 has `json()` and `json_each()` support). Enable foreign keys with `PRAGMA foreign_keys = ON`.

## 2. Table Definitions

---

### 2.1 `organizations`

```sql
CREATE TABLE organizations (
  organization_id   TEXT PRIMARY KEY,          -- UUID generated by app
  name              TEXT NOT NULL,
  created_at        TEXT NOT NULL,             -- ISO 8601 UTC
  updated_at        TEXT NOT NULL
);
```

**Indexes:**
- PK on `organization_id`

---

### 2.2 `teams`

```sql
CREATE TABLE teams (
  team_id           TEXT PRIMARY KEY,
  organization_id   TEXT NOT NULL REFERENCES organizations(organization_id) ON DELETE CASCADE,
  name              TEXT NOT NULL,
  created_at        TEXT NOT NULL,
  updated_at        TEXT NOT NULL
);
```

**Indexes:**
- PK on `team_id`
- Index on `organization_id`

---

### 2.3 `members`

```sql
CREATE TABLE members (
  member_id         TEXT PRIMARY KEY,
  team_id           TEXT NOT NULL REFERENCES teams(team_id) ON DELETE CASCADE,
  role_profile_id   TEXT REFERENCES role_profiles(role_profile_id) ON DELETE SET NULL,
  display_name      TEXT NOT NULL,
  external_id       TEXT,                 -- GitHub handle, Slack ID, etc.
  created_at        TEXT NOT NULL,
  updated_at        TEXT NOT NULL
);
```

**Indexes:**
- PK on `member_id`
- Index on `team_id`
- Index on `role_profile_id`

**Constraints:**
- `team_id` is NOT NULL (member must belong to a team)

---

### 2.4 `role_profiles`

```sql
CREATE TABLE role_profiles (
  role_profile_id              TEXT PRIMARY KEY,
  role_name                    TEXT NOT NULL UNIQUE,
  expected_dimension_weights   TEXT NOT NULL DEFAULT '{}',   -- JSON
  expected_opportunity_levels  TEXT NOT NULL DEFAULT '{}',   -- JSON
  expected_maturity_ranges     TEXT NOT NULL DEFAULT '{}',   -- JSON
  created_at                   TEXT NOT NULL,
  updated_at                   TEXT NOT NULL
);
```

**Notes:**
- Pre-seeded with standard roles: Junior Backend, Mid Backend, Senior Backend, Junior Frontend, Mid Frontend, Senior Frontend, Senior Fullstack, Tech Lead, DevOps Engineer
- JSON fields keyed by `dimension_id`

---

### 2.5 `personal_baselines`

```sql
CREATE TABLE personal_baselines (
  baseline_id          TEXT PRIMARY KEY,
  member_id            TEXT NOT NULL UNIQUE REFERENCES members(member_id) ON DELETE CASCADE,
  baseline_dimensions  TEXT NOT NULL DEFAULT '{}',    -- JSON
  created_by           TEXT,
  notes                TEXT,
  baseline_created_at  TEXT NOT NULL
);
```

**Constraints:**
- One baseline per member (`UNIQUE` on `member_id`)

---

### 2.6 `analysis_runs`

```sql
CREATE TABLE analysis_runs (
  analysis_run_id     TEXT PRIMARY KEY,
  member_id           TEXT NOT NULL REFERENCES members(member_id) ON DELETE CASCADE,
  organization_id     TEXT NOT NULL,
  team_id             TEXT NOT NULL,
  role_profile_id     TEXT,               -- snapshot of role at run time
  period_start        TEXT NOT NULL,      -- ISO date YYYY-MM-DD
  period_end          TEXT NOT NULL,
  run_type            TEXT NOT NULL
                        CHECK (run_type IN ('fresh', 'refresh_same_period', 'refresh_new_period', 'compare_period')),
  status              TEXT NOT NULL DEFAULT 'pending'
                        CHECK (status IN ('pending', 'collecting', 'analyzing', 'completed', 'failed')),
  triggered_by        TEXT,
  scoring_version     TEXT,
  taxonomy_version    TEXT,
  created_at          TEXT NOT NULL,
  completed_at        TEXT,
  error_message       TEXT
  -- Period length validation enforced at application layer (max 365 days)
);
```

**Indexes:**
- PK on `analysis_run_id`
- Index on `member_id`
- Index on `(member_id, period_start, period_end)`
- Index on `status` (for job polling)

**Business rules:**
- `period_end - period_start` must not exceed 365 days (enforced at app layer too)
- Only one `status = 'analyzing'` run per member at a time (enforced at app layer)

### 2.9 `behavioral_events`

```sql
CREATE TABLE behavioral_events (
  event_id               TEXT PRIMARY KEY,
  analysis_run_id        TEXT NOT NULL REFERENCES analysis_runs(analysis_run_id) ON DELETE CASCADE,
  member_id              TEXT NOT NULL,
  timestamp              TEXT NOT NULL,
  source_evidence_ids    TEXT NOT NULL DEFAULT '[]',   -- JSON array

  event_summary          TEXT,
  polarity               TEXT NOT NULL CHECK (polarity IN ('positive', 'negative', 'mixed', 'neutral')),
  severity               REAL,
  event_confidence       REAL,
  impact_level           TEXT CHECK (impact_level IN ('low', 'medium', 'high')),
  opportunity_level      TEXT CHECK (opportunity_level IN ('none', 'low', 'medium', 'high')),
  related_dimensions     TEXT NOT NULL DEFAULT '[]',   -- JSON array
  project_id             TEXT,
  workstream_id          TEXT,
  ambiguity_notes        TEXT DEFAULT '[]',
  tags                   TEXT DEFAULT '[]'
);
```

**Indexes:**
- PK on `event_id`
- Index on `analysis_run_id`
- Index on `(member_id, event_type)`

### 2.10 `dimension_signals`

```sql
CREATE TABLE dimension_signals (
  signal_id                TEXT PRIMARY KEY,

  member_id                TEXT NOT NULL,

  source_event_ids         TEXT NOT NULL DEFAULT '[]',    -- JSON array

  signal_strength          REAL,
  signal_specificity       REAL,
  signal_confidence        REAL,
  project_diversity_score  REAL,
  time_spread_score        REAL,
  opportunity_level        TEXT CHECK (opportunity_level IN ('none', 'low', 'medium', 'high')),
  explanation_summary      TEXT
);
```

**Indexes:**
- Index on `(analysis_run_id, dimension_id)`

### 2.11 `dimension_scores`

```sql
CREATE TABLE dimension_scores (
  score_id                    TEXT PRIMARY KEY,
  analysis_run_id             TEXT NOT NULL REFERENCES analysis_runs(analysis_run_id) ON DELETE CASCADE,
  member_id                   TEXT NOT NULL,
  dimension_id                TEXT NOT NULL,
  raw_score                   REAL,
  normalized_score            REAL,
  maturity_level              TEXT NOT NULL,
  confidence_score            REAL,
  confidence_label            TEXT CHECK (confidence_label IN ('low', 'moderate', 'high')),
  opportunity_score           REAL,
  opportunity_label           TEXT CHECK (opportunity_label IN ('none', 'low', 'medium', 'high')),
  delta_value                 REAL,
  delta_label                 TEXT,
  total_signals               INTEGER NOT NULL DEFAULT 0,
  positive_signals            INTEGER NOT NULL DEFAULT 0,
  negative_signals            INTEGER NOT NULL DEFAULT 0,
  mixed_signals               INTEGER NOT NULL DEFAULT 0,
  explanation_summary         TEXT,
  limitation_notes            TEXT DEFAULT '[]',          -- JSON array
  top_supporting_evidence_ids TEXT DEFAULT '[]',          -- JSON array
  top_counter_evidence_ids    TEXT DEFAULT '[]',          -- JSON array
  ui_summary                  TEXT,

  UNIQUE (analysis_run_id, dimension_id)
);
```

**Indexes:**
- PK on `score_id`
- Unique on `(analysis_run_id, dimension_id)`
- Index on `member_id`

### 2.15 `milestones`

```sql
CREATE TABLE milestones (
  milestone_id              TEXT PRIMARY KEY,
  member_id                 TEXT NOT NULL REFERENCES members(member_id) ON DELETE CASCADE,
  source_analysis_run_id    TEXT REFERENCES analysis_runs(analysis_run_id) ON DELETE SET NULL,
  timestamp                 TEXT NOT NULL,
  milestone_type            TEXT NOT NULL,
  title                     TEXT NOT NULL,
  summary                   TEXT,
  impact_score              REAL,
  supporting_event_ids      TEXT DEFAULT '[]',    -- JSON array
  supporting_evidence_ids   TEXT DEFAULT '[]',    -- JSON array
  retained                  INTEGER NOT NULL DEFAULT 1,   -- 1 = true, 0 = false (SQLite has no BOOLEAN)

);
```

**Indexes:**
- PK on `milestone_id`
- Index on `member_id`
- Index on `(member_id, timestamp)` for timeline queries

**Retention:**
- Soft-delete via `retained = false` (not hard delete)
- Retention cap: 5 years from timestamp

### 2.16 `validation_flags`

```sql
CREATE TABLE validation_flags (

  analysis_run_id  TEXT NOT NULL REFERENCES analysis_runs(analysis_run_id) ON DELETE CASCADE,
  target_type      TEXT NOT NULL
```

**Indexes:**
- Index on `(analysis_run_id, target_type, target_id)`

**Preservation:**
- Flags are preserved on same-period refresh (not deleted when snapshot is overwritten)

## 3. Key Read Patterns

| Query | Tables | Notes |
|-------|--------|-------|
| Get member profile (latest run) | `analysis_runs`, `analysis_snapshots` | Filter by `member_id`, `status = 'completed'`, order by `period_end DESC` |
| Load Overview tab | `analysis_snapshots`, `dimension_scores`, `category_scores` | One snapshot, join scores |
| Load Competency tab | `dimension_scores` | Filter by `analysis_run_id`, all dimensions |
| Evidence trace | `evidence_units` | Filter by `evidence_id` |
| Load KPT tab | `kpt_items` | Filter by `analysis_run_id`, order by `item_type`, `display_order` |
| Load Case Feedback tab | `case_feedbacks` | Filter by `analysis_run_id`, order by `impact_level`, `display_order` |
| Load Journey tab | `milestones` | Filter by `member_id`, order by `timestamp` |
| Validation flags for run | `validation_flags` | Filter by `analysis_run_id` |
| Navigation sidebar | `organizations`, `teams`, `members` | Hierarchical join |
| Analysis run status (polling) | `analysis_runs` | Filter by `analysis_run_id`, select `status` |

## 4. Key Write Patterns

| Operation | Tables | Notes |
|-----------|--------|-------|
| Create org/team/member | `organizations`, `teams`, `members` | Simple insert |
| Trigger analysis | `analysis_runs` | Insert with `status = 'pending'` |
| Collect evidence | `source_payloads`, `evidence_units` | Batch insert |
| Store events | `behavioral_events` | Batch insert |
| Store signals | `dimension_signals` | Batch insert |
| Store dimension scores | `dimension_scores` | Upsert on `(analysis_run_id, dimension_id)` |
| Store category scores | `category_scores` | Upsert on `(analysis_run_id, category_id)` |
| Store KPT | `kpt_items` | Delete existing + insert new (per run) |
| Store case feedback | `case_feedbacks` | Delete existing + insert new (per run) |
| Store milestones | `milestones` | Append only, never overwrite |
| Persist snapshot | `analysis_snapshots` | Upsert on `analysis_run_id` |
| User validation | `validation_flags` | Insert |
| Update run status | `analysis_runs` | Update `status`, `completed_at` |

## 5. Constraints & Validation Rules

> SQLite note: Enable FK enforcement with `PRAGMA foreign_keys = ON` at connection startup.
> Range constraints (e.g. 0–1 float, 1–5 score) are enforced at application layer since SQLite CHECK constraints are permissive.

| Rule | Location |
|------|----------|
| Period max 365 days | App layer validation (date diff check before insert) |
| One baseline per member | UNIQUE on `personal_baselines.member_id` (SQLite enforces) |
| One snapshot per run | UNIQUE on `analysis_snapshots.analysis_run_id` (SQLite enforces) |
| Score range 1–5 | App layer validation |
| Confidence range 0–1 | App layer validation |
| Only valid status transitions | App layer state machine |
| Milestone max 5 years | App layer / background cleanup job |
| Boolean fields (`retained`, `p8_approved`) | Stored as INTEGER 0/1, interpreted as bool in app |

---

## 6. Snapshot Persistence Strategy

- `analysis_snapshots` is written once when a run reaches `completed`
- On **same-period refresh**: overwrite `analysis_snapshots`, overwrite `dimension_scores`/`category_scores`/`kpt_items`/`case_feedbacks`, preserve `validation_flags`, preserve `milestones`
- On **new-period refresh**: create new `analysis_run` and new snapshot; all prior runs/snapshots remain unchanged
- Raw tables (`evidence_units`, `behavioral_events`, `dimension_signals`) are retained per run for traceability

---

## 7. Historical Storage Strategy

| Data | Retention |
|------|-----------|
| Milestones | Up to 5 years, soft-delete only |
| Analysis runs + snapshots | Retained indefinitely (no automatic purge in MVP) |
| Validation flags | Retained with their run |
| Evidence / events / signals | Retained with their run (can be archived after 2 years if needed) |
